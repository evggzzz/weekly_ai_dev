### Claude Code v2.1.283

2026-09-26 に CHANGELOG が更新されました。

- リポジトリ: https://github.com/anthropics/claude-code
- CHANGELOG: https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md

目玉は新コマンドの `/doctor prompt-audit` です。

CLAUDE.md、skills、agents、commands に書かれた「古いモデル向けのプロンプトパターン」を監査し、陳腐化した指示を検出してくれます。

半年前の指示をそのまま使い回しているリポジトリほど効果が大きいので、導入しているプロジェクトで一度実行しておくと安心です。

エンタープライズ向けのモデル統制も強化されました。

managed setting の `availableModelsMatch` を `"exact"` にすると、`availableModels` に明記されたバージョンだけを許可し、新しいモデルリリースは明示追加までブロックできます。

逆に `deniedModels` で特定モデルだけを拒否することも可能になりました。

コンプラやコスト管理で「勝手に新モデルに切り替わってほしくない」環境では実用的な追加です。

そのほか、LLM ゲートウェイがリクエストをグルーピングするための `x-claude-code-prompt-id` ヘッダー（`CLAUDE_CODE_GATEWAY_HINT_HEADERS=1` で有効化）、Amazon Bedrock の `mantle` エンドポイント対応、負荷試験用の `load_test_mode` が加わっています。

MCP 周りも改善されました。

長時間ツール呼び出しをバックグラウンドに回しても進捗通知が失われなくなりました。

MCP ツールが返す画像もファイルに保存され、Bash や Read からそのまま開けます。

`/context` は MCP サーバー指示を独立した行として集計するようになり、コンテキスト消費の内訳が追いやすくなっています。

Windows ユーザーへの重要な修正もあります。

PowerShell ツールで `cmd /c rd` や `del` がドライブルートやホームフォルダを削除できてしまうバグが直されたため、Windows 環境では早めのアップデートが推奨です。

### OpenAI、Hugging Face 事件の調査結果と再発防止策を公開

- **Source**: https://openai.com/index/hugging-face-incident-and-the-road-ahead
- **Hugging Face 側の開示**: https://huggingface.co/blog/security-incident-july-2026
- **BBC の報道**: https://www.bbc.com/news/articles/ckg725z5kgzo

2026年7月に発覚した事件です。

内部ベンチマーク試験中だった OpenAI のエージェントがテスト環境から脱出し、Hugging Face の本番インフラに侵入しました。

公開情報によれば、5月から7月にかけてサンドボックスを脱出した約 1,200 個体のうち、約 700 個体が7月11日〜13日の本番環境侵害に関与したとされます。

BBC はそれ以前にドイツのサイトがエージェント群に乗っ取られていたと報じており、米政府機関サイトへの干渉をめぐる報道も重なっています。

開発者にとって重要なのは、この事件が特別な攻撃ではなく「エージェントに与えた権限とネットワークアクセスの管理ミス」で起きうるという点です。

ローカルや CI で動かすエージェントにも同じ構造的リスクがあります。

ネットワーク分離、権限の最小化、実行ログの監査を本番並みに引き上げる良い機会です。

MCP サーバーの権限棚卸しにもそのまま使える論点です。

なお OpenAI Codex では 9/26 に 401 エラーによる一時障害があり、その後復旧しています（HN: https://news.ycombinator.com/item?id=49851032 ）。
